# What each build contains

Every ffmpeg-wasi build compiles one FFmpeg release, named below, from `--disable-everything` plus an
explicit allowlist. The tables below are generated from that allowlist, `build/enable-lists.sh`, and a
component is in every build marked `yes`: the conformance suite fails any built artefact that lacks
one. FFmpeg's configure can also switch on what a listed component depends on, such as a parser or a
bitstream filter, so a build may carry a little more than the tables show. Rely only on what is
listed.

For a question about a component's options, such as the bitrates an audio encoder accepts, read
[FFmpeg's own documentation for that release](#ffmpegs-own-documentation): ffmpeg-wasi passes a job's
codec options to libavcodec unchanged.

The columns are `profile/variant`. The [profiles](variants.md) are `lean`, `intermediate` and `full`.
The variants are `lgpl` and `gpl`, set by the [licensing model](../explanation/licensing.md).

## FFmpeg's own documentation

FFmpeg's rendered documentation at [ffmpeg.org](https://ffmpeg.org/documentation.html) is regenerated
nightly from FFmpeg's newest revision, so it can describe options this build's release doesn't have.
For the release ffmpeg-wasi builds, read the documentation sources at that release's tag, which is
the version named in the generated section below:

| Topic | Source at the tag |
|---|---|
| Encoders and their options (bitrates, quality, presets) | [`doc/encoders.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/encoders.texi) |
| Decoders | [`doc/decoders.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/decoders.texi) |
| Options common to every codec | [`doc/codecs.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/codecs.texi) |
| Muxers | [`doc/muxers.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/muxers.texi) |
| Demuxers | [`doc/demuxers.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/demuxers.texi) |
| Options common to every format | [`doc/formats.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/formats.texi) |
| Filters | [`doc/filters.texi`](https://github.com/FFmpeg/FFmpeg/blob/n9.0.1/doc/filters.texi) |

Those pages describe the `ffmpeg` command line too, which ffmpeg-wasi does not ship. Read them for a
component's options, and use [the job-spec vocabulary](job-spec.md) for how a job sets them.

## What is left out, and why

- **Anything GPL in the `lgpl` builds.** The `gpl` variant adds `--enable-gpl` and libx264, and in
  `full` libx265. The `lgpl` variant enables no GPL component, so its artefacts stay LGPL. See
  [the licensing model](../explanation/licensing.md).
- **Anything non-free.** No build passes `--enable-nonfree`, so no artefact links a library whose
  licence forbids redistribution, such as libfdk_aac. AAC encode is FFmpeg's native `aac`.
- **HEVC and AV1 encode from WASM.** They are native-only, in `full`. See
  [limits](limits.md#can-i-encode-hevc-or-av1-from-the-wasm-module).
- **Hardware acceleration, and the `ffmpeg` command line.** See [limits](limits.md).
- **Specific omissions people ask about**, such as `eq` and DTS encode. See
  [limits](limits.md#what-is-deliberately-left-out-of-the-codec-and-filter-sets).

The narrative pages on [codecs](codecs.md), [filters](filters.md) and [containers](containers.md)
explain what each batch is for. The tables below list every component each build is checked to carry.
